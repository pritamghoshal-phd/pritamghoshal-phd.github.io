Exploiting bistability and viscoelasticity in reservoir computing

Mechanical systems have no delay line. Viscoelasticity is the only way a structure can remember — so I built a reservoir computer around it.

Role: Lead author · Co-authors: J. M. Gibert, A. K. Bajaj
Reservoir computing Bistable chains Melnikov analysis MATLAB Electronics

The problem

Reservoir computing lets a physical system do the heavy lifting of machine learning. Instead of training a deep network, you feed a signal into a nonlinear dynamical system, let its own physics transform the input into a rich high-dimensional response, and train only a simple linear readout. The appeal for mechanical engineering is obvious: computation with almost no power and no processor.

But a reservoir has to satisfy one hard requirement — it must retain recent inputs while gradually forgetting older ones. In electrical implementations this fading memory is trivial to arrange with a delay line. In a mechanical system there is no equivalent. Viscoelasticity is the only available mechanism, because a viscoelastic structure's state depends not just on how it is deformed now but on how it has been deformed.

Figure 1 — Reservoir computing architecturerunning

Figure 1. The reservoir itself is never trained — its own physics performs the nonlinear, high-dimensional transformation for free. Each node is a bistable von Mises truss carrying a viscoelastic element, and the nodes are coupled into a chain. Training touches only the linear readout Wout, which is why a mechanical reservoir can run on almost no power.

Figure 2 — The unit cell, liverunning

Figure 2. The unit cell has two jobs. A mass m held by inclined springs k at pinned supports forms a von Mises truss that snaps between two stable states — that snap-through is the nonlinearity. A standard linear solid, spring E∞ in parallel with a Maxwell arm (E1, η), makes the cell's state depend on its deformation history rather than just its current deformation — that is the fading memory. The relaxation time λ = η/E₁ measured against the observation timescale gives the Deborah number, and that single ratio decides which of the two properties dominates.

The reservoir

The unit cell is a bistable von Mises truss coupled to a standard linear solid element. Chained together, these form the reservoir.

  • Bistability supplies strong nonlinearity through snap-through between wells
  • The standard linear solid supplies fading memory with a tunable relaxation time
  • Governing equations derived from first principles
  • Nondimensionalised in terms of the Deborah number and dimensionless stiffness and viscoelastic parameters

Nondimensionalising early was the decision that made the rest tractable — it collapsed a large parameter space into the handful of ratios that actually control behaviour.

Evaluating it

Performance was measured against tasks, not aesthetics:

  • Information rate for discrete tasks such as logic operations
  • Normalised mean-square error for continuous prediction tasks
  • Memory capacity and autocorrelation as direct measures of short-term memory
  • Largest Lyapunov exponent to detect when the reservoir had gone chaotic

Parameter sweeps mapped how performance varies with viscoelastic and excitation parameters, including the finding that near resonance a monostable cell outperforms a bistable one.

The trade-off, made explicit

The central result is that memory and nonlinearity pull against each other, and the Deborah number sets where you sit between them. Increase the relaxation time and memory improves while the useful nonlinearity washes out; shorten it and the reverse happens. There is no universally optimal setting — the right balance depends on the task, and the paper shows how to tune toward it deliberately rather than by search.

Push too far and the unit cells become chaotic, at which point prediction collapses entirely. To characterise that boundary analytically rather than empirically, I developed a framework based on Melnikov's method that predicts the transition from optimal to poor reservoir performance. It gives a design criterion instead of a warning after the fact.

A physical breadboard implementation was built to check that the behaviour survives contact with real hardware, and it reproduced logic operations with reasonable fidelity.

Figure 3 — Memory–nonlinearity trade-off, live running

Figure 3. An eight-cell chain driven by a random input stream. Cell brightness tracks instantaneous state and an amber ring fires whenever a cell snaps between wells — that snapping is the nonlinearity the readout exploits. Below, the input against the reservoir's response. On the right, the trade-off: memory capacity climbs with the Deborah number while effective nonlinearity falls away, and the shaded band marks where useful computation lives. Drag De and watch both operating points move — push it low and the reservoir forgets too quickly, push it high and the dynamics smooth out until there is nothing left to separate one input from another.
